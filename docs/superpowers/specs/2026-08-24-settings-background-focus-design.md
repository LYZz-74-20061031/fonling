# 设置角色卡片背景取景设计

## 目标

设置首页“当前角色”卡片与聊天主界面继续使用同一张用户背景图，但允许两处采用不同的显示位置。卡片取景不生成第二张图片，不修改原图，也不影响聊天背景现有显示。

## 用户体验

1. 用户仍从“数据、外观与安全 → 聊天背景”上传一张角色背景图。
2. 上传成功后，聊天背景沿用当前 `cover + center` 逻辑。
3. 当角色已有背景图时，同一区域显示“调整卡片取景”按钮；没有背景图时隐藏或禁用该按钮。
4. 点击后打开全屏取景页，顶部固定显示“取消 / 卡片取景 / 保存”。
5. 页面中央显示与设置首页角色卡片相同比例的裁切框。用户拖动图片调整主体位置；图片始终使用 `cover`，不会出现空白边缘，也不会被拉伸。
6. “重置取景”恢复智能默认位置。点击“保存”后，设置首页立即使用新位置；点击“取消”或关闭时放弃本次调整。
7. 更换背景图后，旧取景坐标自动重置，避免把上一张图片的位置错误套用到新图。
8. 重置默认背景时，同时清除卡片取景位置。没有用户背景时，当前角色卡片显示暖色纯色底，不使用内置角色图片。

## 数据结构

每个智能体的设置新增：

```js
bgCardFocus: {
  x: 50,
  y: 35
}
```

- `x`、`y` 均为 `0` 到 `100` 的百分比坐标，对应 CSS `background-position`。
- 默认值为 `50, 35`，让常见竖版人物图优先显示中上部。
- 读取旧角色或旧 JSON 时缺失该字段，直接使用默认值，不需要破坏性迁移。
- 非数字、无穷值或越界值会被归一化并限制在 `0...100`。
- `saveCurrentCharacter`、角色快照保存、JSON 导出、JSON 导入和清空流程必须保留该字段。
- “清空全部剧情与记忆”不改变背景或取景；“重置默认背景”清除背景并恢复默认取景。

## 取景交互

取景页只编辑一份草稿坐标：

- 打开时复制当前已保存坐标。
- Pointer/Touch 拖动换算为归一化坐标；横向图片可调 `x`，竖向图片主要调 `y`。
- 拖动范围根据图片尺寸、预览框尺寸和 `cover` 缩放结果计算，确保任何位置都不会露出底色。
- 保存时先更新 `state.bgCardFocus`，再调用现有原子保存函数；保存失败时恢复原坐标并保留取景页，显示现有存储警告。
- 取消时不写入 `state` 或 `localStorage`。

## 组件边界

- `js/settings/settings-ui.js`：新增纯函数 `normalizeBackgroundFocus` 和基于图片/框尺寸计算拖动坐标的函数，便于 Node 测试。
- `index.html`：增加取景页结构、打开/拖动/重置/保存事件，以及角色状态的保存、导入、导出接线。
- `css/settings.css`：增加全屏取景页、裁切框和操作按钮样式；角色卡片使用动态 `background-position`。
- 删除当前工作树中的 `assets/settings-character-fallback.png`，并移除设置面板和角色卡片对该素材的引用。

## 错误与兼容处理

- 图片仍沿用现有上传、压缩和存储逻辑；本功能不改变图片编码质量或最大尺寸。
- 图片尚未完成加载时，保存按钮禁用并显示加载状态。
- 图片加载失败时不修改原坐标，允许取消退出或重置背景。
- Pointer Events 不可用时仍可通过两个范围控件调整水平和垂直位置，保证键盘和旧设备可操作。
- 角色 JSON 只增加两个小数值；不会明显增加导出文件或本地存储大小。

## 验收标准

- 同一张背景图在聊天区和设置卡片中可显示不同位置。
- 竖版人物图在横向卡片中可以把面部调整到合适区域。
- 拖动过程中不变形、不露出空白边缘。
- 保存后刷新页面、切换角色以及导出再导入，取景位置保持一致。
- 取消调整不会改变已保存取景。
- 更换或重置背景后不会沿用旧图坐标。
- 无背景角色不再显示内置角色图片。
- 390 × 844 视口无横向溢出，取景页的取消和保存按钮始终可见。
