# 角色改名、SSE 完整性与静态 PWA 图标设计

## 目标

在保持单文件应用主体结构和现有使用习惯的前提下：

- 修复对话身份改名后当前身份与切换按钮仍使用旧名称的问题。
- 修复 SSE 流结束时尾部 UTF-8 数据或无换行最后一帧可能未处理的问题。
- 使用可替换的静态 PNG 文件提供稳定的 Chrome/PWA 图标。
- 将产品名称统一为“智能剧情故事”。

## 范围约束

- 保留 DeepSeek API、角色档案、聊天记录、摘要、导入导出和本地存储结构。
- 不处理摘要期间快速发送、流式回复期间切换智能体、中文档案名称大小写、API Key 明文存储等已接受风险。
- 不在本次任务中实现自动备份或新的数据安全设置；任务完成后提供防丢指导。
- 不增加第三方运行时依赖或构建步骤。
- 继续支持直接部署静态文件并在 Chrome 中添加到手机主屏幕。

## 角色改名设计

新增集中式角色改名函数。函数接收角色索引和新名称，先读取旧名称，再更新角色对象。如果 `state.currentRole` 等于旧名称，则同步更新为新名称。完成后保存当前智能体，并重绘角色列表、聊天消息和当前身份栏。

角色名称输入框的 `change` 事件只调用该函数。角色列表重绘后，“切换”按钮重新绑定新名称，不再持有过期闭包。现有空名称行为保持不变，不新增重名校验或迁移规则。

## SSE 数据完整性设计

提取一个由普通发送和“重说”共同使用的 SSE 流读取函数。该函数：

1. 使用一个 `TextDecoder` 和字符串缓冲区读取响应体。
2. 每个网络块通过 `decode(value, { stream: true })` 追加到缓冲区。
3. 按换行提取完整 SSE 行，并解析 `data:` 后的 JSON。
4. 流结束时调用无参数的 `decoder.decode()`，将解码器尾部内容追加到缓冲区。
5. 解析最终没有换行符的剩余缓冲区。
6. 忽略空行、`[DONE]`、非 `data:` 行和无法解析的行。
7. 每获得内容增量时调用回调，以保留现有流式显示。

函数返回完整回复文本。发送和重说流程只负责创建消息对象、调用读取函数、保存结果和处理错误，避免两份 SSE 逻辑继续分叉。

## 静态图标与名称设计

新增文件：

- `manifest.webmanifest`
- `icons/icon-192.png`
- `icons/icon-512.png`

用户提供一张正方形 PNG 源图，推荐 1024×1024，最低 512×512。实现时将生成两个目标尺寸。`index.html` 在 `<head>` 中直接链接 Manifest、favicon 和 Apple Touch Icon；删除运行时生成 Blob Manifest 和 Canvas 图标的 `setupPWA()` 逻辑。

以下名称统一改为“智能剧情故事”：

- HTML `<title>`
- 登录页标题
- 脚本顶部说明文字
- Manifest `name` 和 `short_name`

Manifest 使用固定 `start_url`、`scope`、`display: standalone` 和 `orientation: portrait`，图标同时声明 `any` 与 `maskable` 用途。以后替换图标时，覆盖两个同名 PNG；Chrome 已安装版本需要移除后重新添加到主屏幕以确保刷新图标。

## 错误处理

- SSE 单行解析失败时继续读取后续行，行为与当前实现一致。
- 响应体不存在或读取失败时沿用现有网络错误处理，不保存空的流式回复。
- 图标属于静态部署资源；若文件缺失，网页主体仍可运行，但浏览器可能使用默认站点图标。

## 测试与验收

先写并观察失败的回归测试，再修改生产代码：

- 当前选中的角色改名后，`state.currentRole` 更新为新名称，数据被保存，角色列表、消息和身份栏被刷新。
- 非当前角色改名不会错误修改 `state.currentRole`。
- SSE 中文或 emoji 被拆分到多个字节块后仍完整返回。
- 最后一条 SSE `data:` 帧没有换行时仍被解析。
- 普通发送和重说共同使用同一读取逻辑。
- HTML、Manifest 和登录页均显示“智能剧情故事”。
- Manifest 引用 192×192 与 512×512 静态 PNG。

最终运行全部 Node 测试、内嵌 JavaScript 语法检查，并用手机尺寸浏览器验证名称、图标链接和基础页面加载。
