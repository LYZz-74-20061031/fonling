# Fonling 章节系统 v1 设计

日期：2026-08-23  
状态：待用户审阅  
项目：智能剧情故事

## 1. 目标与范围

章节系统是可选的手动剧情整理工具，不是聊天的前置条件。用户可以在任意时刻开始一个章节、为其命名，并在一轮完整对话后主动结束章节。章节结束后，系统使用免费 GLM 生成一份待确认的压缩摘要；用户确认的章节摘要作为长期剧情背景进入后续模型上下文。

v1 只支持单线剧情，不提供剧情分支、存档点、章节重新打开、跨章回溯、章节删除或单章节导出。

## 2. 核心产品规则

### 2.1 可选章节

- 没有进行中章节时可以正常聊天。
- 同一智能体最多有一个进行中章节。
- 章节从创建后的下一条用户消息开始。
- 不属于章节的对话继续使用现有滚动摘要；超过近期窗口的非章节原文可以删除，只保留摘要。
- 章节之间允许存在任意数量的非章节对话。

### 2.2 章节原文

- 章节内每轮成功保存的用户消息和 AI 回复永久保存。
- 章节管理中的原文只读，只保存阅读所需的角色、显示名称和纯文字。
- 主聊天界面不永久渲染全部章节原文，继续只保留近期消息窗口。
- 用户在章节详情中通过“阅读原文”查看该章完整对话。

### 2.3 已结束章节

- 已结束章节不可重新打开、删除、编辑原文或回溯。
- 回溯不能跨越章节边界。
- 已结束章节允许改名、手动编辑确认摘要，或生成新的待确认摘要草稿。
- 删除整个智能体或执行“清空聊天记录”可以删除其全部章节。

## 3. 技术架构

章节系统作为与结构化记忆同级的独立模块：

```text
js/chapter/
├─ chapter-model.js
├─ chapter-storage.js
├─ chapter-context.js
├─ chapter-controller.js
└─ chapter-ui.js
```

- `chapter-model.js`：实体标准化、状态转换、章节边界和纯数据操作。
- `chapter-storage.js`：章节版本迁移、导入校验、序列化和存储空间估算。
- `chapter-context.js`：剧情摘要层格式化、相关性排序和预算选择。
- `chapter-controller.js`：开始、取消、结束、改名、归档、确认摘要和重新生成。
- `chapter-ui.js`：章节状态、章节管理、待确认提示、摘要编辑和只读原文。
- `index.html`：协调消息发送、回溯、滚动压缩、模型网关、角色保存和章节模块。

章节模块不得复制模型请求网关或角色持久化逻辑。

## 4. 数据模型

每个智能体新增：

```js
{
  chapterSchemaVersion: 1,
  chapters: [],
  activeChapterId: null
}
```

章节实体：

```js
{
  id: "chapter_...",
  name: "第一章",
  status: "active" | "ended",
  revision: 1,
  startedAt: "ISO-8601",
  endedAt: "ISO-8601" | "",

  messages: [
    {
      id: "message_...",
      role: "user" | "assistant",
      speakerName: "主控" | "角色名" | "智能体名",
      content: "纯文字"
    }
  ],

  rollingSummary: "",
  rollingSummaryThroughMessageId: "",

  summary: {
    confirmedText: "",
    confirmedAt: "",

    draftStatus: "none" | "generating" | "ready" | "failed",
    draftText: "",
    generatedAt: "",
    lastFailure: null,

    sourceSceneText: ""
  }
}
```

约束：

- 章节 ID 和消息 ID 不可变；名称可以重复。
- `activeChapterId` 必须为空，或指向唯一的 `active` 章节。
- `ended` 章节必须包含至少一轮完整对话和结束时间。
- 章节原文中的消息 ID 必须唯一，并与主聊天中仍存在的同一消息保持一致。
- `confirmedText` 只有在用户确认后才能进入模型上下文；生成替代草稿时继续使用已有确认文本。
- `sourceSceneText` 是结束时捕获的内部摘要输入，不作为独立场景快照展示，并在首次摘要确认后清空。
- `revision` 在边界、原文或摘要状态发生有效修改时递增，用于拒绝过期异步结果。

不保存独立的结束场景快照。时间、地点、人物状态和未解决冲突由最终章节摘要正文概括。

## 5. 章节生命周期

### 5.1 开始与取消

- 只能在设置面板的章节管理中开始章节。
- 创建窗口默认填写“第 N 章”，用户必须提供非空名称。
- 章节从创建后的下一条用户消息开始，不追溯纳入已有对话。
- 空章节可以取消；取消后不生成摘要，也不占用后续默认编号。
- 包含任何成功保存对话的章节不能取消，只能结束。

### 5.2 写入原文

- 用户消息与 AI 回复完整生成并成功保存后，作为一轮原子追加到活动章节。
- 模型请求失败时不留下半轮章节原文。
- 编辑最新 AI 回复时同步更新章节副本。
- 免费重新回复或 Air 重新深度思考成功时，以新 AI 消息替换章节中的旧回复。
- 保存失败时恢复主消息、章节原文、摘要、记忆候选、分析状态和请求追踪。

### 5.3 回溯

- 只允许回溯主聊天近期窗口中、当前活动章节内的消息。
- 章节开始前、非当前章节和已结束章节的消息不显示可用回溯入口。
- 回溯同步截断活动章节原文，并删除被移除消息派生的候选记忆、分析状态和请求追踪。
- 回复生成期间禁止编辑、回溯、结束章节或切换智能体。

### 5.4 结束

- 章节至少包含一轮完整的“用户消息 + AI 回复”。
- 最新消息必须是完整生成并成功保存的 AI 回复。
- 结束操作显示不可逆确认说明。
- 用户确认后先原子冻结章节边界并保存，再启动摘要请求。
- 冻结边界时把当前场景格式化为内部 `sourceSceneText`，仅供首次摘要生成或失败重试使用。
- 章节一旦结束不能恢复为活动状态。
- 摘要生成不阻塞普通聊天、智能体切换或开始下一章。

## 6. 滚动压缩与原文归档

主聊天继续沿用既有阈值：原始消息超过 30 条时压缩，成功后保留最近 14 条。

每条主聊天消息增加内部 `chapterId`。被移出主界面时：

- 活动或待确认章节的消息已经存在于章节原文中，因此主消息可以删除；这些消息合并进对应章节的内部滚动摘要。
- 已确认章节的消息直接从主消息移除，不再重复生成内部摘要。
- 非章节消息合并进现有非章节滚动摘要，原文不再保留。
- 一次压缩跨越不同归属时，必须按 `chapterId` 分组处理，不能把章节和非章节内容混成不可拆分的摘要。
- 压缩失败、返回空内容或保存失败时，不移动消息，不修改任何摘要。

章节内部滚动摘要是系统上下文，不需要用户确认；最终章节摘要草稿仍必须确认。

## 7. 最终章节摘要

### 7.1 生成输入

结束章节后，摘要请求使用：

```text
章节内部滚动摘要
+ 尚未纳入滚动摘要的章节近期原文
+ 章节结束时的当前场景文字
```

不一次性提交整章全部原文。

### 7.2 模型与输出

- 固定使用免费的 `glm-4.7-flash`。
- GLM 明确关闭 thinking。
- 只按免费 GLM 现有规则对网络错误、429 或 5xx 自动重试一次。
- 目标长度为 600–1000 个中文字，硬上限约 1200 字。
- 摘要必须覆盖重要事件、人物与关系变化、关键承诺或信息、章节结束状态及未解决冲突或伏笔。
- 删除对白复述、过程性动作和无关细节。

### 7.3 确认流程

- AI 输出只写入 `draftText`，`draftStatus` 变为 `ready`。
- 用户可以确认、编辑后确认、重新生成或稍后处理。
- 不提供永久忽略或删除摘要；每个已结束章节最终至少需要一份完整确认摘要。
- 未确认草稿绝不发送给剧情模型。
- 重新生成已有确认摘要时，旧确认摘要继续生效；新草稿确认后才原子替换。
- 生成失败时保留旧确认摘要；首次生成失败则保留临时过渡上下文，并允许重试或手动填写。

## 8. 临时过渡上下文

章节结束到摘要确认之间：

- 完整原文已经归档。
- 新的最终摘要草稿不进入模型请求。
- 对应章节的内部滚动摘要和主聊天近期原文继续临时参与上下文，避免后续剧情失忆。
- 近期原文自然超过窗口时，继续补入该章内部滚动摘要。
- 用户确认最终摘要后，系统原子停止使用内部滚动摘要，改用确认摘要。
- 用户长期不确认时，提示持续存在，过渡上下文持续生效。

## 9. 剧情摘要层与上下文选择

章节摘要与非章节滚动摘要属于同级的长期“剧情摘要层”，但不是正式结构化记忆。

总预算约 6000 字符，选择优先级：

1. 当前活动章节的内部滚动摘要，以及所有尚未确认章节的过渡摘要；多个待确认章节按结束时间由新到旧选入预算。
2. 最近一个已确认章节，固定标记为“上回剧情”。
3. 非章节滚动摘要。
4. 更早已确认章节，按本轮用户消息、当前场景和近期对话的相关性选择。

超出预算时先舍弃相关度最低的旧章节。剧情摘要层不得挤占当前场景、固定记忆、相关结构化记忆或最近 14 条原文。

最终请求顺序：

```text
AI 人设与世界观
→ 用户身份、回复风格和当前角色
→ 当前场景
→ 固定及相关结构化记忆
→ 剧情摘要层
→ 最近 14 条原始消息
→ 本轮用户消息
```

每次剧情请求追踪增加：

```js
{
  chapterSummaryIds: [],
  usedActiveChapterRollingSummary: false,
  usedUnchapteredSummary: false
}
```

“查看本次使用的记忆”同时展示使用过的章节摘要。

## 10. 章节与结构化记忆

- 章节摘要不自动拆成历史事件或关键信息。
- 结束章节不清空、不重置当前场景。
- 开始新章节沿用当前场景。
- 现有记忆分析继续独立提出最多 3 条候选，必须由用户确认。
- 章节摘要与正式记忆冲突时，以当前场景和正式结构化记忆为准。

## 11. 界面设计

现有模型状态控制条调整为：

```text
深度思考 ｜ 当前章节：章节名称或“无” ｜ 当前身份
```

- 中间章节区域只显示状态，不响应点击。
- 长名称单行省略，不能挤压左右控件。
- 所有章节操作位于设置 → 章节管理。

章节管理包含：

- 当前章节：名称、消息数量、改名、结束或空章节取消。
- 待确认摘要：确认、编辑后确认、重新生成、稍后处理。
- 已结束章节：按结束时间倒序显示名称、消息数量和摘要状态。
- 章节详情：只包含“章节摘要”和“阅读原文”。

状态控制条附近增加章节提示：

- `有新的章节摘要待确认`
- `章节摘要生成失败，请处理`

提示样式和行为复用现有新记忆提示。多个待处理摘要统一进入待处理列表，处理完毕后提示自动消失。

## 12. 清空聊天记录

“清空聊天记录”重新定义为保留角色配置、彻底重置剧情状态，效果等同于未聊过天的新智能体。

保留：

- 智能体名称。
- AI 人设与世界观。
- 回复风格。
- 主控身份。
- 其他身份角色及颜色。
- 聊天背景。
- 全局 API Key 和模型配置。

清除：

- 主聊天消息及全部滚动摘要。
- 活动和已结束的全部章节、原文与摘要。
- 历史事件、关键信息和当前场景。
- 待确认记忆、记忆分析状态和请求追踪。
- 待确认章节摘要、失败状态和后台请求状态。

清空后自动切回主控身份。活动章节不阻止清空，但流式回复期间仍禁止执行。清空使全部相关请求 epoch 失效，迟到结果不能恢复已删除数据。保存失败时恢复清空前的完整状态。

## 13. 存储、迁移与导入导出

章节数据随智能体设置进入现有角色数据键，主聊天消息继续使用消息键。所有修改沿用双键原子保存和原始字节回滚。

版本：

```text
chapterSchemaVersion = 1
export_version = 3
memorySchemaVersion = 2
```

迁移规则：

- 旧角色初始化空章节列表和空活动章节 ID。
- 旧滚动摘要保留为非章节摘要。
- 旧消息没有章节归属，统一视为非章节消息。
- 导入前校验章节 ID、唯一活动章节、消息结构、状态组合和摘要字段。
- 未来更高章节版本或导出版本明确拒绝。
- 迁移、导入或保存失败时保留原始角色状态和原始存储字节。

章节随现有单智能体 JSON 完整导入导出，不提供单章节导出。全局 API Key 和模型配置仍不导出。

## 14. 异步竞态与错误处理

摘要请求携带角色名、章节 ID、章节修订号和请求 epoch。提交结果前重新加载最新快照并验证：

- 目标智能体仍存在。
- 目标章节仍存在且已经结束。
- 章节修订号和请求 epoch 仍匹配。
- 清空、重新生成或新确认没有使请求过期。

过期结果静默丢弃。返回空内容、超出硬上限或解析失败不得覆盖确认摘要。存储空间不足时复用现有备份警告，并允许立即导出整个智能体备份。

## 15. 测试与验收

自动化测试至少覆盖：

- 章节实体标准化、状态转换、唯一活动章节和不可变边界。
- 开始、空章节取消、结束、改名和跨章回溯限制。
- 成功轮次原子归档，以及请求或保存失败不留下半轮原文。
- 编辑、免费重新回复和 Air 重新深度思考同步章节原文。
- 30/14 压缩、跨归属分组和压缩失败不丢原文。
- 最终摘要生成、确认、编辑、重新生成、手动填写和过期请求竞态。
- 6000 字符预算、最近章节固定、旧章节相关性选择和稳定排序。
- 章节摘要进入请求追踪。
- 旧数据迁移、未来版本拒绝、导入导出和双键回滚。
- 清空聊天彻底删除剧情状态并保留角色配置。
- 切换智能体、删除智能体、清空、回溯与后台摘要请求的竞态。
- 手机章节状态、章节管理、待确认提示和只读原文结构。

完成前验收：

- 全部 Node 回归测试通过。
- `index.html` 内嵌脚本及所有章节、记忆、模型模块语法检查通过。
- `git diff --check` 通过。
- 桌面视口和 390 × 844 手机视口无横向溢出。
- 状态栏、章节管理、摘要确认、长原文阅读和清空确认正常。
- 浏览器控制台无相关错误或警告。
- 使用测试 Key 或由用户亲自验证真实 GLM 摘要调用；源码和测试中不得写入真实 API Key。

## 16. 非目标

v1 不实现：

- 剧情分支或存档点。
- 自动开始或自动结束章节。
- AI 自动命名章节。
- 章节删除、重新打开或原文编辑。
- 跨章节回溯。
- 单章节导出。
- 独立结束场景快照。
- 章节摘要自动转为正式结构化记忆。
